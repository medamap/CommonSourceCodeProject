# FDC ソースリプレイス

## 概要

- src/vm/mb8877.cpp src/vm/mb8877.h はもともと XM7 というエミュレータ由来で GPLv2 と互換性がないためライセンス違反となる
- そのため、ライセンス的に問題のない別のソースと差し替え、mb8877.cpp 同等の機能を用意する必要がある
- とりあえずMB8877をどうにかするならMAMEの最新からwd_fdc関連( https://github.com/mamedev/mame/blob/master/src/devices/machine/wd_fdc.cpp など)を拾ってきて対応させるのが良い
- タイミングまわりと、実際のディスクとのやりとりの仕組みが全然違うので、元のソースのそのあたりを読み解きつつ、慎重に組み込んでいかないと駄目

## 目的

  - wd_fdc.cpp を CommonSourceCodeProject に移植し mb8877.cpp|h と差し替えることでライセンス問題を回避する

## 注意点

  - mb8877.cpp はイベント駆動によるコード、wd_fdc.cpp はステートマシン駆動と仕組みがそもそも異なる

## 移植手法

  - mb8877.cpp と同じパブリックメソッド及びフィールドを用意し、抽象化することで互換性を担保する
  - テストコードを事前に生成し、オリジナルの mb8877.cpp に対するテストスイートを作成する
  - wd_fdc.cpp からコードを抽出し、メソッド及びフィールドを実装することで移植を行う
  - テストスイートをクリアするまで wd_fdc.cpp から抽出移植したメソッドの処理を調整する

## 実装エージェントの管理

  - mb8877.cpp および wd_fdc.cpp のコードは大規模コードとなるため単一の Claude code エージェントによる作業は推奨できない
  - 複数のターミナルを起動し、それぞれ Claude code を実行することで責任範囲を限定することでコンテキストウインドウの肥大を防止する
  - 各エージェントの連携協調は docs フォルダ以下に共有用のステータス md ファイルを生成し、お互い参照しあう事で行うこととする
  - トップレベルのエージェントはプロジェクトマネージャ、通称 PMエージェントとして進行管理を行う
  - PMエージェントはこのファイルの内容のみ把握しており、各エージェントの報告をもとに次の指示ファイルを作成し、新しいエージェントに引き継ぎ、作業を継続させる、場合によっては複数のエージェント指示を作成し、進行管理を行う、それぞれのエージェントには必ずレポート提出を義務づけ、PMエージェントはレポートmdファイルを参照したうえで状況判断を行い、指示を作成する
  - ソースコードの解析および報告はPMエージェントの責任範囲ではない、必ず調査内容を指示書に書き出ししたうえで別エージェントに作業をさせること
  - エージェントの分割基準としては、調査、環境整備、実装、ビルド、レビュー、デバッグ、検証などである
  - PMエージェントもコンテキストウインドウが肥大した場合、次のPMエージェント引き継ぎ資料を作成し、引き継ぎを行う

## エージェントへの作業指示の出し方

  - エージェントの任命はPMが行うが、実作業はユーザーが行う
  - PMは下記のように発言する

```
あたらしいターミナルを起動し、下記コマンドを実行します
cd {現在の作業フォルダ}
claude

次の作業指示を与えてください
あなたは ⚪︎⚪︎Agent です、{作業の指示概要}
指示ファイル docs/instructions/{作業の指示ファイル名}.md を読み込んで、指示通りに作業してください
```

  - なお、指示ファイルの中には、作業完了時のレポートファイル名 docs/reports/{レポートファイル名}.md も指示しておきます
  - 指示ファイルの中には、作業が完了したら、ユーザーへの報告及び、レポートファイルの提出を義務付けます
