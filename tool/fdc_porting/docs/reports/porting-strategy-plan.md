# MB8877からwd_fdcへの移植戦略計画書

## 策定日時
2025年1月10日

## エグゼクティブサマリー

本計画書は、CommonSourceCodeProjectにおけるMB8877 FDCエミュレーションをMAMEのwd_fdcベース実装へ移植するための包括的な戦略を提示します。この移植により、コードの保守性向上、精度の改善、ライセンス問題の解決が期待されます。

主要な推奨事項：
- 3段階のフェーズドアプローチを採用
- 既存インターフェースを維持するラッパークラス方式
- 総実装期間：5-8週間（2-3名の開発者）
- リスク軽減のため元実装を参照実装として保持

## 技術的アプローチの詳細

### アーキテクチャ設計

#### 1. クラス階層設計
```
wd_fdc_device_base (MAME)
    └── wd_fdc_analog_device_base
            └── mb8877_device (新規作成)
```

mb8877_deviceは以下の役割を担います：
- 既存のMB8877インターフェースを完全に維持
- 内部でwd_fdc_analog_device_baseの機能を活用
- MB8877固有の拡張機能を追加実装

#### 2. インターフェース変換層

**I/Oメソッドマッピング：**
```cpp
// MB8877既存インターフェース → WD_FDCメソッド
write_io8(offset, data) → write(offset, data)
read_io8(offset) → read(offset)
write_signal(id, data, mask) → 個別シグナルメソッド
write_dma_io8(offset, data) → data_w(data)
read_dma_io8(offset) → data_r()
```

**シグナルハンドリング変換：**
- SIG_MB8877_DRIVEREG → 内部レジスタ管理
- SIG_MB8877_SIDEREG → side_control設定
- SIG_MB8877_MOTOR → motor_control設定

#### 3. イベント駆動からステートマシンへの変換

**イベントマッピング：**
- EVENT_SEEK → SEEK_MOVE/SEEK_WAIT_STEP_TIME states
- EVENT_SEEKEND → SEEK_DONE state completion  
- EVENT_SEARCH → SCAN_ID with SEARCH_ADDRESS_MARK live state
- EVENT_DRQ → ステートマシン内部で自動処理
- EVENT_MULTI1/2 → MB89311専用ハンドラ実装
- EVENT_LOST → タイムアウト検出ロジック

### タイミング管理戦略

#### 1. マイクロ秒精度の維持
- MB8877の相対時間計算をWD_FDCの絶対時間（attotime）へ変換
- 特殊ディスク用のタイミング調整パラメータを導入
- get_usec()相当の精度を維持

#### 2. PLL同期の調整
- 標準的なディスクフォーマット用のPLLパラメータ設定
- 特殊フォーマット検出時の動的PLL調整
- チェックポイント/ロールバック機能の活用

## リスク分析と対策

### 高リスク項目

#### 1. タイミング互換性問題
**リスク：** 特殊ディスクフォーマットが正しく読めない可能性
**影響度：** 高
**対策：**
- 詳細なタイミング測定とログ機能
- オリジナル実装との比較テスト
- タイミング調整用の設定パラメータ

#### 2. ステートマシン変換の複雑性
**リスク：** イベント駆動ロジックの正確な再現が困難
**影響度：** 中
**対策：**
- 詳細な状態遷移ドキュメント作成
- 段階的な実装とテスト
- デバッグトレース機能の充実

#### 3. パフォーマンス劣化
**リスク：** ラッパー層によるオーバーヘッド
**影響度：** 低〜中
**対策：**
- インライン化による最適化
- プロファイリングによるボトルネック特定
- 必要に応じた直接実装

### 中リスク項目

#### 1. 未知の非互換性
**リスク：** テストで発見されない互換性問題
**影響度：** 中
**対策：**
- 実機ソフトウェアでの広範なテスト
- ユーザーベータテスト期間の設定
- フォールバック機能の実装

#### 2. メンテナンス負荷
**リスク：** 2つの実装を維持する必要性
**影響度：** 低
**対策：**
- 段階的な移行計画
- 十分な検証後の旧実装削除
- ドキュメントの充実
